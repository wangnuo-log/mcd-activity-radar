# 麦麦活动雷达

## 这个技能解决什么

麦当劳的活动信息散落在一堆渠道里：新品、联名限定周边、限时优惠、门店派对活动。
用户想知道「**这个月有什么值得抢**」，得自己刷 App、翻推文、加各种群，还经常错过
开抢时间（例如「10月15日10:45联名徽章开售」，错过就没了）。

本技能把麦当劳 MCP 的活动数据拉下来，**分类 + 排序 + 算倒计时**，一句话交付。

## 核心原则：取数给 MCP，算术给代码，表达给你

**不要用大模型去解析日期、算倒计时、做去重。** 这三件事一律交给
`scripts/radar_engine.py`，因为它：

- 能把「10月15日10:45开售」这种非结构化文案精确解析成时间点；
- 能识别活动日历里同一活动跨多天重复出现、自动合并；
- 能识别同名不同文案（联名第一弹棒球帽 / 第二弹徽章）是**两个**活动；
- 结果可复现、可测试（41 项自测）。

你的职责是：**跑脚本 → 读结果 → 用人话讲给用户听**。

## 执行流程

### 第 1 步：判断模式

- 用户只是想看看 / 首次使用 / **没有配置 Token** → 用 `--demo`（离线样本，无需 Token）
- 用户要**真实数据** → 用 `--live`（需要环境变量 `MCD_MCP_TOKEN`）

> ⚠️ **一定要先试离线 demo**。如果用户还没配好麦当劳 MCP 连接器，直接跑 `--live` 会报
> 「缺少 MCP Token」。此时改用 demo 并告诉用户「这是离线演示数据，配好 Token 后能拉实时活动」。

### 第 2 步：跑脚本

```bash
cd skills/mcd-activity-radar/scripts

# 离线演示（默认，无需 Token）——推荐首次使用
python radar_cli.py --demo

# 真实数据
MCD_MCP_TOKEN="<用户的token>" python radar_cli.py --live
```

常用参数：

| 参数 | 作用 |
|---|---|
| `--demo` | 离线样本，任何人 clone 后即可跑通 |
| `--live` | 接入真实麦当劳 MCP |
| `--json` | 输出结构化 JSON（便于你二次加工，如生成图表） |
| `--only 联名限定` | 只看某一类情报 |
| `--today 2026-10-20` | 覆盖基准日期（演示未来视角） |
| `--categories` | 列出全部情报类别 |
| `--fortune` | 只出「今日手气·随机选餐」（娱乐彩蛋） |
| `--seed N` | 固定抽样种子，结果可复现 |
| `--no-fortune` | 雷达输出中不带随机选餐彩蛋 |

### 第 3 步：读结果并汇报

脚本输出一份 markdown 报告，包含 6 块：

1. **⏰ 开抢倒计时** —— 最该关注的部分，按时间排序，直接给结论
2. **🔥 正在进行** —— 当前在搞的活动，按类别分组
3. **📅 即将到来** —— 未来活动，标了开抢时间
4. **🎁 限定周边** —— 积分兑换的限量周边（含兑换窗口）
5. **🎉 门店活动** —— 可预约的派对/品鉴会/体验营（含 spuId 和价格）
6. **👤 你的账户** —— 用户积分，含「即将过期积分」提醒

**汇报要求**：

- **先给一句话结论**（用 `summarize` 的输出），再展开细节
- 有开抢倒计时的，**必须用加粗把倒计时说出来**（这是这个技能最大价值）
- 用户账户有「即将过期积分」的，**主动提醒**别浪费
- 不要复述整份报告。挑 3-5 条最相关的讲清楚

### 第 4 步：按需跟进（可选）

雷达只负责「发现」。如果用户要**行动**，再调用对应 MCP 工具：

| 用户意图 | 下一步 |
|---|---|
| 想预约门店派对/品鉴会 | `query-party-city`（需 spuId）→ `query-party-store` → `query-party-store-date` → `query-party-store-session` → `party-order-create` |
| 想把新品吃掉 | `query-nearby-stores` → `query-meals` → `calculate-price` → `create-order` |
| 想用积分换周边 | `mall-product-detail`（看 SKU）→ `mall-create-order` |
| 想领券 | `auto-bind-coupons` |
| 想知道能换什么 | `query-my-account`（看积分）对比 `mall-points-products` |

## 彩蛋：今日手气 · 随机选餐（娱乐向）

雷达解决「**有什么**」，随机选餐彩蛋解决「**吃什么**」。当用户说「今天吃什么 / 选择困难 / 摇一卦」
一类的话时，跑：

```bash
python radar_cli.py --fortune            # 只出随机选餐彩蛋
python radar_cli.py --fortune --seed 42  # 固定种子可复现
```

它做一件事：**以传统卦象作为随机符号，从今日真实在售餐品里替你挑一个「随机之选」**。

- 抽样 → 装卦（纳甲 / 纳支 / 八宫归属 / 世应 / 六亲 / 六神，全部查表确定性计算）
  → 按世爻六神映射口味线索 → 从真实菜单选出主推 1 个 + 备选 2 个。
- 引擎在 `scripts/qian_engine.py`，纯标准库，**不依赖大模型心算**，同 seed 结果完全可复现。
- 默认随雷达一起输出；`--no-fortune` 可关闭。

> ⚖️ **合规边界（必须遵守）**：这只是**娱乐性的随机选餐游戏**，卦象仅作随机符号，
> **不是占卜，不做预测**。汇报时**不要**出现「占卜 / 预测 / 运势 / 吉凶 / 算命」这类词，
> 也不要把结果讲成对未来的判断。输出自带免责声明，**不要删**。

## 情报分类（引擎自动完成，无需你判断）

| 类别 | 命中关键词 |
|---|---|
| 门店活动 | 派对、体验营、品鉴会、读书会、过家家、亲子 |
| 联名限定 | 联名、限定、周边、徽章、丝巾、棒球帽、珍藏、限量 |
| 抽奖福利 | 抽奖、霸王餐、麦金喜 |
| 新品上市 | 上新、新品、登场、回归、来啦、首发 |
| 优惠福利 | 券、优惠、折、免配、学生、麦金卡、早餐卡、套餐 |
| 其他 | 未命中以上 |

## 使用的麦当劳 MCP Tool

| Tool | 用途 | 运行方式 |
|---|---|---|
| `campaign-calendar` | 当月活动日历（往期/今日/未来） | `--live` 自动调用 |
| `mall-points-products` | 限定周边（`2>8`）、门店活动（`1>6>20/21/22/25/34/40`） | `--live` 自动调用 |
| `query-my-account` | 用户积分账户（含即将过期积分） | `--live` 自动调用 |
| `query-nearby-stores` + `query-meals` | 门店在售菜单（「今日手气」选餐池） | 样本采集（已脱敏固化为 `sample_data/menu.json`） |
| `now-time-info` | 服务器时间（倒计时基准） | 可选校准（默认用本机时间） |

完整 Tool 说明见 `references/mcp-tools.md`。

## 边界与免责

- 本技能只做**信息聚合与计算**，不替用户下单；下单需用户明确确认。
- 活动与价格以麦当劳官方渠道**实时结果**为准，脚本输出可能滞后。
- 不调用 `draw-lottery` 等带博彩观感的工具；抽奖类活动**只做提醒，不代抽**。
- 本项目为麦当劳程序员节创意开发大赛参赛作品，**非麦当劳官方产品**。
