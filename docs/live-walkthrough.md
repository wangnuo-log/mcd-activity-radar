# 端到端实跑记录：WorkBuddy × 麦当劳 MCP

> **运行环境**：WorkBuddy 自定义连接器 `mcd-mcp`
> **接入参数**：`https://mcp.mcd.cn` · Streamable HTTP · `Authorization: Bearer <MCP_TOKEN>`
> **数据性质**：以下全部为**真实调用返回**，未做任何人为构造。活动为时间敏感内容，实际以麦当劳官方渠道为准。

## 场景

用户在 WorkBuddy 对话中输入：

> 「麦当劳最近有什么值得抢的？」

Agent 依次调用 4 个 MCP Tool，再由**确定性引擎**（`radar_engine.py`，纯标准库）做解析、去重、倒计时计算和分类。

## Step 4 · 账户资产

`query-my-account` → HTTP 200（`accountId` 已脱敏）

```json
{"availablePoint": "61.8", "accumulativePoint": "6424.8",
 "expiredPoint": "5581", "usedPoint": "782",
 "currentMouthExpirePoint": "0", "nextMouthExpirePoint": "0"}
```

> 累计 6424.8 分，其中 **5581 分已过期**——积分是会过期作废的资产，这是雷达「资产提醒」能力的依据。

---

## Step 5 · 确定性加工（不是大模型心算）

`radar_engine.py` 处理以上原始数据：

**① 去重**：活动日历里同一活动跨多天重复出现，「今日」小节实际是**当前全部在进行的活动**快照。
去重键 = `(标题, 文案)` —— 因为 GD 联名第一弹（棒球帽）与第二弹（徽章）**标题相同、文案不同**，必须算两条。

**② 倒计时**：正则抽出「X月X日 HH:MM 开售/开抢」+ `datetime` 计算，可复现、可测试。
（营销文案里的「积分抢先购10:40开抢」只有时间无日期，需回落到活动当天）

**③ 分类**：按关键词把活动归入 5 个情报类别 —— 门店活动 / 联名限定 / 抽奖福利 / 新品上市 / 优惠福利。

输出样例见 [`demo-output.md`](./demo-output.md)（离线可复现版）。
